1. **HIGH — Reconcile can still destroy “Save Only” restart authorisation. Remaining-from-round-1; 2.0.2.**  
   [ProfilesStore.swift:866](native/App/Stores/ProfilesStore.swift:866), [TunnelController.swift:1844](native/Packages/TunnelEngine/Sources/TunnelEngine/Controller/TunnelController.swift:1844).

   Edit a connected OpenVPN kill-switch profile and choose Save Only while validation remains unavailable or times out. The new local revision becomes unverified. Reconcile filters it out of `local`, interprets the existing remote profile as deleted, and calls `removeProfile`. That removes the previously approved payload, credentials and persisted start authorisation while the connected session continues. Its subsequent NE replay receives 225 before the protective hold, leaving the Mac open.

   **Fix:** Separate profiles eligible for provisioning from profiles that still exist locally. Retain the last approved remote revision and session authorisation until an approved replacement or explicit removal.

   **Coverage:** Existing tests cover successful higher-revision provisioning and initially unverified imports separately. Add connected → unverified Save Only → reconcile → provider restart.

2. **HIGH — `revokeUnattended` deletes authorisation during the NE restart gap. New-in-round-2; 2.0.2.**  
   [TunnelController.swift:1326](native/Packages/TunnelEngine/Sources/TunnelEngine/Controller/TunnelController.swift:1326), [ProfilesStore.swift:878](native/App/Stores/ProfilesStore.swift:878).

   An unattended kill-switch session remains connected after Auto-Connect is disabled. Following `providerFailed`, `noNetwork`, or process replacement, `session?.key` is absent. If the GUI reconciles before NE restarts that session, revocation deletes its retained unattended record. The legitimate non-manual replay then receives 225 and opens the connection.

   This is distinct from risk 29’s acknowledged window for outside starts: the revocation intended to close that window also destroys legitimate recovery.

   **Fix:** Track restart eligibility beyond the in-memory session’s lifetime. Separate withdrawing consent for new unattended sessions from terminating an existing session’s replay authorisation.

   **Coverage:** [StartAuthorisationTests.swift:237](native/Packages/TunnelEngine/Tests/TunnelEngineTests/StartAuthorisationTests.swift:237) explicitly expects deletion after `providerFailed`. Replace that expectation with a crash → revoke → successful NE replay regression.

3. **MEDIUM — Unauthenticated settings still provide automatic-start proxies. Remaining-from-round-1; 2.0.2 authorisation gap.**  
   [ManagerQuiescer.swift:52](native/App/Stores/ManagerQuiescer.swift:52), [ManagerConfiguration.swift:100](native/App/Model/ManagerConfiguration.swift:100).

   Same-user malware can write `pendingResume.profileID` in `settings.json` and launch the genuine app. Successful activation invokes `resumeAfterUpdate`, which passes that unauthenticated target to `returnOnDemand` → `connect`, obtaining a fresh arm and nonce. A saved manual WireGuard profile needs no further credential interaction.

   Independently, editing `autoConnect.enabled` and `autoConnect.profileID` makes the genuine app manufacture unattended consent. The explicit enabled flag is still attacker-writable.

   **Fix:** Authenticate update-resume records and Auto-Connect consent, including their target profile and purpose. Validate them before creating rules or arming starts.

   **Coverage:** The new forged-record tests cover `PausedState`, leaving these other persisted start instructions unchecked.

4. **MEDIUM — Pause can sign an attacker-chosen resume target. New-in-round-2; 2.0.2.**  
   [ConnectionStore.swift:2114](native/App/Stores/ConnectionStore.swift:2114).

   `pause()` prefers an existing `pausedState.profileID` over the active profile, then creates a fresh HMAC without verifying the old record. Malware can plant an unsigned `pausedState` naming profile B, with no `pausedUntil`. Launch does not discard that record. When the user later pauses connected profile A, LockPlus signs B as the resume target; expiry legitimately passes the new HMAC check and starts B.

   **Fix:** Reuse an old pause target only after validating its existing intent and pause end. Otherwise derive the target from the current session.

   **Coverage:** Add an unsigned or expired existing record naming B, pause while A is connected, and assert that B never receives an intent or start.

5. **MEDIUM — Probe timeout loses evidence of traffic leaving outside the tunnel. New-in-round-2; 2.0.2.**  
   [ConnectionSelfTest.swift:425](native/App/Services/ConnectionSelfTest.swift:425), [ConnectionSelfTest.swift:437](native/App/Services/ConnectionSelfTest.swift:437).

   A probe can transition `.waiting(noPath)` → `.ready` on `en0`, send its GET, then stall. `.ready` retains the earlier waiting failure. The timer constructs a result without `wasReady`, interface or local address, but with that stale `.noPath`. For an IPv4-only full tunnel expecting IPv6 blocking, classification produces a green blocked/absent verdict despite the successful outside connection. A malicious network can manipulate path availability and stall the response.

   **Fix:** Clear stale waiting evidence on readiness and preserve readiness/interface evidence through timeout and every other terminal path.

   **Coverage:** Current tests construct terminal `ProbeFetch` values directly. Add the actual waiting → ready → timeout sequence.

6. **MEDIUM — IPv6 blocking evidence concerns a different destination. New-in-round-2; 2.0.2.**  
   [ConnectionSelfTest.swift:276](native/App/Services/ConnectionSelfTest.swift:276), [ConnectionSelfTest.swift:196](native/App/Services/ConnectionSelfTest.swift:196).

   The connection resolves the probe hostname, but an unreachable result is checked against the hard-coded address `2606:50c0:8000::153`. A malicious LAN can supply another AAAA address, route that destination outside an IPv4-only tunnel, and return ICMP unreachable. The hard-coded address can still route through the blackhole utun, producing a green result. Additionally, `nil` from the route lookup includes socket/read failures, yet is treated as proof of no route.

   **Fix:** Associate evidence with the actual attempted remote endpoint. Distinguish a confirmed local rejection from lookup failure; uncertainty must remain inconclusive.

   **Coverage:** Test different resolved and hard-coded destinations, plus route-query errors. Existing boolean/interface fixtures conceal both distinctions.

7. **MEDIUM — Split DNS can still be labelled “Through the tunnel” on `en0`. Remaining-from-round-1; 2.0.2 self-test.**  
   [DNSVerifier.swift:76](native/App/Services/DNSVerifier.swift:76), [ConnectionSelfTest.swift:205](native/App/Services/ConnectionSelfTest.swift:205).

   With split DNS, matching expected nameserver addresses can yield `.ok` without checking the resolver interface. `combineDNS` then skips route verification, while the presentation labels `.ok` “Through the tunnel.” For example, the physical network and split profile can both name the same public resolver; ordinary DNS remains on the physical network but receives a green tunnel claim.

   **Fix:** Verify the relevant resolver scopes and their paths, and present split DNS accurately instead of translating configuration agreement into tunnel-path proof.

   **Coverage:** [ConnectionSelfTestTests.swift:200](native/Tests/LockPlusTests/ConnectionSelfTestTests.swift:200) currently expects `.ok` for the split/en0 case.

8. **LOW — Large profile collections prevent consent revocation. New-in-round-2; 2.0.2.**  
   [ProfilesStore.swift:710](native/App/Stores/ProfilesStore.swift:710), [LPWire.swift:64](native/Packages/LockPlusCore/Sources/LPWire/LPWire.swift:64).

   Revocation sends up to 500 UUIDs, but its request inherits a 16 KiB limit. A 500-UUID binary plist exceeds that limit, so the client rejects it before sending. The app only logs the failure and subsequently retries the same oversized batch. Profiles beyond the first 500 are also omitted indefinitely. Retained unattended authorisations therefore survive withdrawal of consent.

   **Fix:** Batch all IDs within the encoded byte limit.

   **Coverage:** Add maximum-size wire round trips and collections exceeding one batch; current revocation tests use small collections.

9. **LOW — Timeout retry can reconnect to the process awaiting watchdog exit. New-in-round-2; 2.0.2.**  
   [ValidatorClient.swift:108](native/Packages/LockPlusCore/Sources/LPXPCClient/ValidatorClient.swift:108), [ValidatorServiceHandler.swift:53](native/Packages/ProfileValidator/Sources/LPValidatorService/ValidatorServiceHandler.swift:53).

   Apple documents one embedded service process per client process; creating another connection can reach the same process. [Apple XPC documentation](https://developer.apple.com/documentation/xpc).

   After replying `.timeout`, the service waits 250 ms before exiting. The client immediately reconnects and retries during that interval. The watchdog exit can then count as a crash of the retry, even when its evaluation never ran. Combined with one earlier actual crash, this can incorrectly produce permanent `.profileCheckCrashed` instead of the intended timeout outcome.

   **Fix:** Coordinate termination and verify a new service generation before retrying; distinguish expected watchdog exits from evaluation crashes.

   **Coverage:** Existing tests count connections against an in-process fake whose watchdog action never exits. Add a real service-process test.
