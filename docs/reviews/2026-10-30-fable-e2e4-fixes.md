## Flaky test: `ControllerConnectedTests.pathIsDebounced` (TunnelEngineTests/ControllerConnectedTests.swift:60)
Cause: `h.advance(h.clock, by: 500ms, sleepers: 2)` waits for `sleeperCount >= 2`. `ManualClock.sleeperCount` counts `.waiting` slots only; a cancelled sleeper is removed (`ManualClock.swift:51-58`), so the re-armed debounce after `wifi` leaves the count at 2 — indistinguishable from the `none` debounce. The count is already 2 as soon as the controller has processed `none` (watchdog + none-debounce). If the controller's `for await` + actor hop has not yet consumed `wifi` when `waitUntil` returns, the clock advances, the `none` timer fires, `pathSettled()` sees `none` → `.reasserting(.noNetwork)` → the `#expect` fails. The 5 ms real-time sleep is the only ordering guarantee; conversely, under load `none` may be dropped by `.bufferingNewest(1)` and the test passes vacuously. The trailing 20 ms sleep is a real-time negative check.
Deterministic fix: make `pathState.pending` return the pending `PathSnapshot?` (`TunnelController.swift:1152`), then: send `none` → `waitUntil { pathState.pending == none }`; send `wifi` → `waitUntil { pathState.pending == wifi }`; `h.clock.advance(by: 500ms)`; `waitUntil { pathState.pending == nil }`; assert `pathState.settled == wifi`, `phase == .connected`, `reconnectReasons.isEmpty`. No real-time sleeps. (Alternative: a monotonically increasing `sleepersEverCreated` on `ManualClock` and wait for `before + 2`.)
