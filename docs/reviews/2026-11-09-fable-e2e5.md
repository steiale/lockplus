# Security review: E2E-5 migration fixes (10316d1 … af9ce41)

Read-only. Nothing above MEDIUM. No injection, TOCTOU or out-of-scope deletion found in the F1 script; the findings are about network state, prompt hygiene and copy honesty.

## F1 privileged removal (`native/App/Services/LegacyHelperRemoval.swift`, `LegacyAppDetector.swift:252-282`)

**What holds up (verified against the Go source):**
- Paths/label/anchor/pin all match 1.x: `internal/elevate/spawn_darwin.go:27-45` (label, plist, binary, log, team `M53GHX9FAY`, identifiers `lockplus-helper`/`openvpn`), `internal/ipc/transport.go:10` (socket), `internal/firewall/darwin.go:15,26` (anchor `com.apple/wireguide`, `pf-was-enabled`), `internal/tunnel/recovery.go:23` (`tunnel-states`), `internal/helper/helper.go:174` (`ovpn-run`), `dns_journal.go:20`.
- Injection: no interpolation; the only `$(...)` are `stat/find/pfctl/PlistBuddy` used in `[ ]` comparisons or `-n` tests; `p.environment = ["PATH": …]` (:138) strips the caller's env (IFS/BASH_ENV/locale can't reach the root shell); the script re-pins PATH; all paths absolute (cwd irrelevant); `/bin/sh` → bash here (`/var/select/sh`). The script is the first non-option argv and never starts with `-`; the localized prompt is argv 2 after it, so osascript's getopt can't misread either. The script is data, never AppleScript source.
- TOCTOU/symlinks: every parent of a deleted path is root-owned and not group/other-writable (`/Library/LaunchDaemons` 755, `/Library/PrivilegedHelperTools` 1775, `/var/log` 755, `/Library/Application Support` 755 root:admin so the Go GUI's own `MkdirAll` at `internal/storage/paths.go:89` fails and `$D` is created by root 0755; `/var/run` is group `daemon`, not the user). The user cannot rename/replace anything between the checks and `rm`; `rm -rf` on `$D/{tunnel-states,ovpn-run}` is reached only after `$D` is root-owned, not a symlink, and the subdirs are `-d && ! -L`. `rm` never follows a top-level symlink; `-S` on the socket then `rm -f` removes only the entry.
- Signature: `codesign --verify --strict -R=…` with the same requirement string the Go installer pins (`spawn_darwin.go:60-62`); binary is in a root-only dir so no post-check swap; dev/ad-hoc builds fail closed (`not-go-binary`).
- Deletion scope: exact constant paths only; `openvpn` only if root-owned and team-signed as `openvpn`; data dir only if root-owned, and kept with journal/marker.
- Results: last `LP_RESULT=` line parsed; `.removed` is only believed after a fresh `lstat` of the plist (`:274`); the only free text surfaced/logged is osascript's stderr (≤300 chars), which carries no secrets.
- Spoofing: the admin prompt is reachable only via `.helperIdle`, which requires the root-owned plist; an unprivileged user can't plant it. Planting `pf-was-enabled`/`dns-journal.json` is impossible without root too.
- Platform: works on 26; on 27 the Go app's identical mechanism was observed in E2E-5 (`RESULTS-E2E-5.md:61`, `:140`) with the extra "Allow administrator access for a script started by LockPlus?" consent. AEWP is deprecated since 10.7 but present. Keep this mechanism; an `SMAppService` daemon would be worse, as the design says.

**Findings**

**F1-1 MEDIUM — removal while the Go GUI runs triggers a second, Go-branded admin prompt that reinstalls the root helper.**
`LegacyHelperStore.removeHelper` (`LegacyAppDetector.swift:257-261`) refuses only on `finding.blocksConnect`; `facts.goGUIRunning` (`:19`) is read but never used. In the Keep Both case (RESULTS §coexistence, both VMs) the Go GUI is open and idle. `launchctl bootout` kills its helper; the Go health monitor (`internal/gui/helper_lifecycle.go:175-240`, ping every 5 s) calls `recoverHelper → ensureHelper → elevate.SpawnHelper` (`:119`), i.e. a new osascript admin prompt ("LockPlus needs administrator access to install its VPN helper service"), up to 6 attempts. Outcome: the user is asked for the admin password twice in a row by two apps with the same name; approving the second reinstalls the daemon seconds after removal, and the native re-read races it (`.removed` reported, helper back). Fix: `guard !facts.goGUIRunning else { removal = .failed(.busy) }` before the prompt, hide the button while `goGUIRunning` (`canRemoveHelper`), and copy "Quit the old LockPlus first".

**F1-2 MEDIUM — "restart your Mac to clear them" is false for DNS; removal can leave the Mac without name resolution.**
`removed-left-state` (`LegacyHelperRemoval.swift:65-67,76`) and `LegacyHelperCopy.removed(leftNetworkState:)` (`LegacyHelperViews.swift:109`) promise a restart clears the leftover. pf rules do clear on reboot; DNS does not: the Go helper sets DNS with `networksetup` (`internal/network/dns.go:244-259`), which persists in the network service's preferences, and the only replay of `dns-journal.json` is the helper's own startup (`helper.go:185-193`). Scenario: helper installed but unreachable without a pf marker → `LegacyFinding.evaluate` returns `.helperIdle` (`LegacyAppDetector.swift:45`) → button offered → script boots out nothing, deletes the helper, keeps `$D` because the journal exists → VPN resolvers stay configured forever, and the thing that would have restored them is gone. Fix (script, before `launchctl bootout`): `if [ -e "$D/dns-journal.json" ] && ! launchctl print "system/$L" >/dev/null 2>&1; then result dns-unrestored; fi` mapped to a refusal whose copy says to open the old LockPlus once (its helper replays the journal) or set DNS back to Automatic in System Settings › Network; and change the `removed-left-state` copy to name DNS and System Settings rather than a restart.

**F1-3 LOW — busy check misses the legacy DNS sub-anchor.** `pfctl -a com.apple/wireguide -s rules` (`:41`) doesn't list `com.apple/wireguide/dns` (`firewall/darwin.go:19`, flushed by newer helpers but loaded by older ones). Add the same test for the sub-anchor.

**F1-4 LOW — admin dialog attribution (prompt hygiene), unverified.** The comment at `:97` says macOS shows "LockPlus wants to make changes." Because `/usr/bin/osascript` is a separate process, the SecurityAgent title on 26 is very likely "osascript wants to make changes" (the 27 pre-consent names LockPlus). Training users to approve an "osascript" admin dialog is the phishing concern the brief asks about. Verify in the next E2E; if so, run the same constant handler in-process (`NSAppleScript`/`OSAScript` with `executeAppleEvent`, passing script and prompt as event parameters, keeping the no-source-interpolation property) so the dialog names LockPlus. Otherwise correct the comment.

**F1-5 LOW — secrets linger when the data dir is kept.** In the `left=yes` branch (`:66-67`) nothing under `$D` is removed, so `ovpn-run` (root-only generated `*.ovpn` with inline keys, `ovpn/manager.go:187`) and `tunnel-states` stay on disk. Remove those two subdirs in both branches; keep only the journal and the marker.

**F1-6 LOW — programmatic guard weaker than the UI.** `removeHelper()` proceeds for `.helperCrashedWithFirewall` (not `blocksConnect`); only the button checks `canRemoveHelper` (`:252`). Use `guard canRemoveHelper` inside `removeHelper()`.

**Inherent, accepted (state in §13.3a):** the script constant lives in the signed binary inside a user-writable `/Applications` bundle; a same-user attacker who patches the binary gets root at the next approval. Same trust model as the Go installer and every `with administrator privileges` app; mitigated only by Gatekeeper/signature on launch.

**Test before GA:** the runner passes an env with only `PATH` (`:138`, no `HOME`/`USER`); osascript + the Security framework should cope, but the design admits it is "not yet run against a live Go helper".

## Focus 2

**F5 LaunchAgent (`LegacyLaunchAgent.swift:35-52`)** — no finding. `lstat` regular file + `st_uid == getuid()` + label pin + `…/Contents/MacOS/lockplus` suffix, then `removeItem`. The lstat→remove window is same-user only (`~/Library/LaunchAgents`), no privilege boundary; no bootout; never registers a login item without asking. `XPC_SERVICE_NAME` spoofing only makes a second instance quit quietly.

**F4 resumable migration (`GoAppMigrator.swift:62-181`)** — secrets OK, idempotence OK, one honesty issue.
- No double import of secrets: resumed credentials skip profiles that already hold a password (`:277`); username-only items are re-saved with identical content; raw keychain bytes are zeroed (`:280`). Profiles are mapped by marker item or payload digest (`:113-118`, `:259-263`), never created twice. `migration.json` holds old name, new UUID, SHA-256 digest, result, home-relative source, steps: no secret; not in the diagnostics bundle (`DiagnosticsBundle.swift` has no migration file). No migrator log line carries payload or credentials.
- **F4-1 LOW (honesty/scope):** `resumes()` (`:85-88`) treats "no marker + any profile whose digest matches the Go data" as an interrupted migration. A user who imported the same `.conf`/`.ovpn` files by hand and never ran the migration gets "Finish importing from LockPlus 1.x — An earlier import didn't finish" in onboarding and, after onboarding, `MigrationResumeBanner` (`MigrationViews.swift:186-193`) at every launch with a single "Finish Import…" button and no "Not Now". "Finish" then runs `applyGlobal` (`:100`), and `applySettings` (`:342-363`) overwrites language, log level, menu-bar icon style and the auto-connect profile/enabled flag, while the copy promises to "add what's missing". Fix: write the marker (`complete: false`, `items: []`) at the top of `run()` before the first `profiles.create`, make `resumes` depend on an incomplete marker only, and give the banner a "Not Now".

**F3 helper re-read** — fine. Per Connect: cached fact or one `lstat`, then one read-only `Tunnel.Status` over a uid-authenticated socket (≤2 s, own serial queue); 5 s polling only while refusing, one loop at a time (`watch` guard), ends when the refusal clears. Concurrent `refresh()` calls both produce fresh facts; last write wins. The socket is only talked to if owned by this uid (`socketIsOurs`) and lives in a root-owned dir, so it can't be faked.

**F7 copy** — honest except the two items above (F1-2 "restart your Mac" for DNS; F4-1 "didn't finish"). "If the old LockPlus offers its update to 1.2 …" is correctly conditional (v1.2.0 is decided, not shipped). Keychain-password wording and "saved logins" match the run.

## Summary
No HIGH. Two MEDIUMs, both in F1's interaction with the Go side: refuse removal while the Go GUI runs (F1-1) and refuse/relabel when an un-replayed DNS journal exists (F1-2). Five LOWs (sub-anchor, dialog attribution, lingering `ovpn-run`, programmatic guard, F4 "finish" heuristic). Injection, TOCTOU, signature pin, deletion scope and result trust are sound.
