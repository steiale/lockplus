# Sonnet review: changes from build 200018 to 200021

Reviewed: `75fddcec..b237fd4a` (owner-test fixes: app icon, appearance setting, palette, import report copy, editor close, logs, chart, menu bar rates).

Review of 75fddcec..HEAD (200018 -> 200021). Base is 75fddcec because 5e1dd5e0 doesn't exist. I read every diff in native, docs and tests; I did not build or run the tests.

## HIGH
**H1. The import report says "Nothing to do" for lines that do change behaviour.** ImportSheets.swift (ImportReportCopy.notNeededExplanation, the `ignored` DisclosureGroup ~L44-52 and L815-818) and ProfileDetailView.swift:156-175 put every `.ignored` item under "not needed ... Nothing to do: the profile works as it is", with a grey info icon.
- GoAppMigrator.harmlessIgnored (L271) deliberately excludes the behaviour-changing ones. Its comment says scripts, web sign-in and WG settings "DO change behaviour". Excluded reasons include .scriptsNeverRun and .verifyHashNotSupported.
- localizedMessage and PreviewData.acme still list script-security and `up` under "not needed".
- Scenario: an .ovpn with `up update-resolv-conf` or `verify-hash <pin>` imports. The sheet says the lines aren't needed, and the pin isn't enforced.
- ImportVerdict still reports .importedWithWarnings, so it now disagrees with the sheet.
- Fix: split .ignored into harmless and behaviour-changing with one shared harmlessIgnored (move it into LPModel).
  - Harmless items keep the info icon and "not needed" copy.
  - The rest get the amber icon, a heading like "N directives not applied", and their reason, with no "Nothing to do" line.
  - ProfileItem.ignoredDirectives needs a `harmless` flag.

## MEDIUM
**M1. Appearance changes made by the app itself never apply live.** UIBinder.swift:333 only applies when after.appearance != before.appearance on the UI -> settings path.
- Migration, or any app-written settings change, goes env.settings -> apply() into the UI model -> settingsFromUI with before == after, so nothing is applied.
- Scenario: migrating a 1.x install with theme "dark" shows Dark in Settings while the app stays in System until relaunch.
- Fix: also call AppAppearanceApplier.apply in the push branch at UIBinder.swift:262-266 when env.settings.value.appearance changed. Add a test. AppAppearanceApplier has no test at all.

**M2. The menu bar rate text may be unreadable under a forced appearance (verify on device).** AppAppearanceApplier sets global NSApp.appearance, but DESIGN claims the status item keeps following the menu bar. MenuBarController.labelAttributes has no explicit foreground colour.
- Scenario: Appearance=Light with a dark menu bar gives dark-on-dark rates.
- Check both directions. If it breaks, set the status button's appearance to nil or use an explicit colour.

**M3. Logs action buttons may render blank (verify).** SectionViews.swift:375-383 applies .labelsHidden().labelStyle(.iconOnly) to the whole ViewThatFits.
- .labelsHidden() can hide the label of a .toggleStyle(.button) Toggle (Follow), leaving an empty button. I couldn't confirm it: the committed Logs screenshot predates the change.
- Fix: scope .labelsHidden() to the Picker and TextField only. .iconOnly already keeps the accessibility labels.

**M4. AccentColor is now #4a6e62 in dark, about 2.9:1 on the dark window.** gen_colors.py ACCENT.
- It drives Link text (About, Help) and the 2 pt focus ring (FormLayout.swift:45). That fails 4.5:1 for text and 3:1 for the ring.
- ContrastTests.accent only checks white on the accent.
- Fix: use a lighter dark accent, e.g. the old #80ae9a, and keep #4a6e62 only for the selection and connectFill. Or tint Links and the focus ring explicitly. Add a contrast test.

**M5. everyIgnoredReasonTextIsDefined can't fail.** OwnerTest1UITests.swift:298-306.
- The `default:` branch of localizedMessage returns message(), and the test asserts localizedMessage() == message(), so a missing case still passes. It also never checks DE.
- Fix: make the ignored switch exhaustive (no default), and assert each key exists in the catalogue with a `de` value.
- MigrationTests.themeParsed and E2E5FixTests use !notes.contains{"\($0)".contains("Appearance")}. That is near-vacuous now that the enum case is deleted.

## LOW
- **L1. Figure space (U+2007) isn't in SF Mono.** Formatters.swift:187. I measured it: CTFontGetGlyphsForCharacters is false, so it falls back to another font. "\u{2007}12K" is 27.02 pt against 27.20 pt for "888M", so the label still shifts about 0.18 pt per pad. A plain space is exactly one digit wide in the mono font (6.7998 pt, the same as "8"). Fix: pad with " " and update the test, which only counts characters.
- **L2. Docs contradict themselves.**
  - DESIGN.md:3210 lists "appearance" in the tabs, then still says "There is no appearance setting ... Theme picker is cut".
  - DESIGN.md:1303 still says the Go theme is dropped.
  - UI-CONCEPT:906 says step 3 triggers saveToPreferences, but with no profile it now doesn't (AppActions.swift:432).
- **L3. Leftovers from the sidebar revert.** The revert is mostly clean: LockGlyph.ink, SidebarSelection, sidebarRowSelected and usesSelectionInk are gone.
  - lp.onSelection is dead. The colorset, Colors.swift:62, the gen_colors.py entry and the DesignTokenTests pair (L168-171) all stay, and nothing in App/ uses it.
  - Stale comments: the SidebarInk doc (SidebarView.swift:120-123) still describes the removed Multicolor .tint mechanism, and L46 says .tint "doesn't reach the selection". The SelectionAppearance doc (L142) says "pastel lp.selection". ConnectButtonStyle.swift:5 still says light is #2d7a68 with white (5.13:1). The gen_colors.py comments at ~L1090 and ~L1104 are stale. The Colors.swift doc for `selection` says "tint of the list".
  - usesOnPastel and pastelSelection now return white text, so the names mislead. Rename them, e.g. usesAccentInk.
- **L4. The render harness and a test use the wrong surface for the selection.** The real selection is AccentColor with white text.
  - ScreenshotTests.swift:198 fills the selected row with lp.selection (pastel in light) and then applies white text, so the render is unreadable and unrepresentative.
  - RenderFixups.swift:24 also draws lp.selection.
  - DesignTokenTests.selectedBadge (L209) tests the badge over lp.selection instead of the accent. The real contrast is fine, about 9:1.
- **L5. Unfocused selection (verify).** SidebarInk forces white when backgroundProminence == .increased. If the unfocused grey selection still reports .increased on 27.3, that is white on grey.
- **L6. VPNConfigurationHint is gated on profile count, not on whether macOS has asked.** Someone who already allowed VPN configurations, deleted all profiles, and imports from Settings > Advanced (MigrationViews.swift:165) is told macOS will ask. It won't.
- **L7. ProfileDetailView.swift:159 uses ForEach(id: \.self) on IgnoredDirective.** Duplicate name+reason pairs give duplicate IDs. Use enumerated offsets or dedupe.
- **L8. CloseGuard edges.** The pattern itself is sound: window-owned guard, weak hook and original, no retain cycle.
  - If the hook is released, windowShouldClose falls through to the original and closes a dirty editor with no prompt.
  - Save and Don't Save call window.close(), which skips windowShouldClose and so the controller path the comment describes.
  - closeSurvivesHookRebuild uses Task.sleep(100ms) where other tests were moved to polling. It also doesn't exercise the updateNSView re-wrap path, where SwiftUI replaces the delegate.
- **L9. Bridge window (SceneSupport.swift:72-74).** Clean and idempotent. The comment ("can end up without its content") is vague. Programmatic close() still works, and no test asserts the style mask lacks .closable.
- **L10. Throughput chart.** The window logic is inline in body, so it can't be tested; extract a static helper. RateChartDescriptor now includes the pre-window sample, so the "Seconds ago" count is off by one.
- **L11. Logs pickers.** Level is a menu now (it was segmented) with a hidden label, so sighted users see a bare "All" or "App and Tunnel". VoiceOver still gets the label.
