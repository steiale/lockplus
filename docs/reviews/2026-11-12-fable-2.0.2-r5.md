## LOW

### L1. A late stop notice still ends the record of a newer session that was admitted as a replay (remaining part of Codex r4 #2 / Fable N1; reproduced)

- `Packages/TunnelEngine/Sources/TunnelEngine/Controller/TunnelController.swift:1476-1480`: a `.replay` admission keeps the matched record unchanged (`guard existing == nil else { return }`), so its `at` stays the first admission's time.
- `:1421`: the notice clears a record when `rec.at <= stop.stoppedAt`. A session admitted by replay after the stop still carries the old `at`, so it reads as the stopped generation.
- Only `.armed` and `.unattended` admissions refresh `at`. The regression test `aLateStopNoticeNeverEndsANewerSession` starts session B with on-demand rules (`.unattended`), so it misses this.
- Scenario:
  1. Kill-switch profile P runs unattended; its rules are then withdrawn (Stay Connected off, or another profile becomes the Auto-Connect one).
  2. P ends with `noNetwork`. The user cancels the recovery; the notice isn't delivered (extension busy, or quit before the hello).
  3. P is started outside LockPlus without options (System Settings, `scutil --nc start`). It is admitted as a replay of the standing record and connects. LockPlus isn't running, so nothing voids the notice.
  4. That session ends without a user stop (Wi-Fi off). The user opens LockPlus during the gap; the notice is delivered.
  5. The record goes. NE's restart gets 225; a failed `includeAllNetworks` start leaves the Mac open.
- Reproduced with a probe on the scratch copy: after step 4 the record is `nil` and the replay ends with `.startNotAuthorised`.
- LOW: a long chain, and the app voids the notice whenever it sees the session Connected. But DESIGN D10.8-3 and risk 31 (4) say a late notice "never" ends a newer session's record, and E2E row R4-G passes only because its profile has rules.

Fix: refresh `at` on every replay admission (`persisted.authorisedStarts[key] = existing ?? matched`, then `.at = now`). `replayOf` in the guard keeps the old time, which is right: a notice arriving during the wait still refers to the record as it was. Test: the existing one with `onDemandRules: false` for B (my probe, expectation inverted). Correct D10.8-3 and risk 31 (4).

### L2. Pause signs a "crash gap" profile that a refused outside start can produce (new in round 5, from the Fable L2d fix; from reading)

- `App/Stores/ConnectionStore.swift:617-619`: `crashGapHolder` is any `.awaitingRestart` entry of an own profile whose session is down.
- `:2245` and `:2295`: Pause now takes it as its target and signs it (`sealRecord(.pause, …)`). At the pause's end the signed app arms and starts that profile.
- Such an entry does not need a session the owner ran. `:420`: a start made elsewhere of an own kill-switch profile without rules, which ends without ever being active, is held as `.awaitingRestart` (`holdForSystemRestart(id, recordCrash: false)`). That includes a start the extension refused with 225.
- The hold ends once the 225 is read and dated to this attempt (`checkNoNetworkRefusal`, `:634-641`); if the error isn't stored yet at the single read, it lasts the full 10 s.
- Scenario: nothing is connected. Another local user (or same-user code) runs `scutil --nc start` on the owner's kill-switch profile P, repeatedly. Each attempt is refused, and each puts P into the hold for about 1 to 10 s; the hero shows "Checking whether P restarts…". The owner presses Pause in such a window. At the pause's end LockPlus arms and starts P with the saved credentials. The refused start has become an authorised one.
- Before round 5 the same Pause had no target. A live session at Pause takes precedence, so this needs nothing active.
- Related and older (not new): offline, the same outside start is refused by NE with "No network available" and becomes the network-restart hold, which this run sealed itself and therefore counts as verified. Pause signs that too, with no time limit while offline.
- LOW: it needs the owner's Pause while the hero visibly shows P recovering, and it starts only the owner's own verified profile. It is the class Codex r3 #4 rated MEDIUM (an unsigned hold as the pause target), reached here through NE state instead of `settings.json`.

Fix: sign a gap or hold as the pause target only when its session is one this app issued the start for, or one this run saw Connected (the crash case the L2d fix was for). Still stop it and send the notice in every case. Apply the same condition to the network-restart hold. Tests: a refused outside start, Pause inside the hold, expect `pausedState.profileID == nil`; the existing `pauseInACrashGapStopsTellsAndResumesIt` stays green.

## NIT

- **N1. The Connect-time void loses a notice (remaining).** `App/Stores/ConnectionStore.swift:1549` voids the pending stop before the arm. If the arm or the start then fails, the old record stands with no notice. With generation binding the void isn't needed here (the new record is newer than the stop); the one at Connected (`:388`) is enough.
- **N2. The fresh attempt repeats for the same revision (new).** `TunnelController.swift:1992` compares the commit with the revision of the configuration NE started with, which never changes during the session. Every later provision of revision 2 (a same-revision retry, a reconcile) resolves the user's new prompt again and restarts the attempt. Compare with the revision the current attempt loaded.
- **N3. Test gap: a stop-only request that also revoked would pass (new).** Mutation M8 (`EngineServiceBackend.swift:133`, treating a nil keep set as empty) passes the whole suite. Add: a stop-only notice leaves another profile's unattended record without a plan untouched.
- **N4. A comment that isn't true.** `App/Headless/HeadlessResume.swift:120`: "every return below that keeps it is for a target". `.networkRestartPending` also returns with no target, after the value was consumed. Harmless (a record with no target has nothing to verify), but the comment should say so.

## Task 2: what the round-4 fixes introduced

- **Generation-bound notices.** Sound apart from L1. Rounding `stoppedAt` down is the right direction: a session admitted after the stop is always newer than the notice. A record admitted in the same second before the stop survives it, which falls back to the round-3 state (the record stands). A clock set back is as FIX4 describes; I found no cheaper cure than the void at Connected.
- **Stop-only wire request.** Validated (`isWireValid`: no pages, no batch, at most 16 stops, finite times). Only the caller's own uid. It can't revoke anything by construction, but that isn't tested (N3).
- **Pending stops in unsigned `settings.json`.** A forged or replayed entry, also one dated in the future, can do one thing: end the record of a profile of the same user whose session is not running in the extension, once, at the next delivery. That is what `scutil --nc stop` in the same gap achieves. It starts nothing, can't touch another user's keys, and is skipped for a live session. A malformed entry drops the whole list, which only loses notices. No finding.
- **Hello retry.** Bounded (five per failed call), stops once capabilities are known, and runs the normal reconcile after success. No finding.
- **Kill-switch guarded starts surviving a commit.** No payload that must not run can run: the kept start loads the committed payload, which only a verified provision writes; a removal, a wipe and the user's stop still end it. The dropped `staleRevision` rule is consistent, since a reservation holder always has `includeAllNetworks`.
- **Fresh attempt at a live prompt.** The old prompt's answer is refused as stale and nothing of it reaches the new attempt (tested). Only N2.
- **120 s orphan grace.** The kept configuration has no profile file, so the app never arms it, and its extension copy is the last verified payload. A user Delete of this run is exempt. No finding.
- **`state.plist` salvage.** Only start authorisations survive; another boot's are still dropped at load; the cap holds. The file is root-owned. My probe with malformed arrays (`"$null"`, wrong types, a dictionary) returned nothing and terminated.
- **Pause in a crash gap.** L2.
- **The agent's stop notices.** Sent only after the agent's own `managers.stop` of a session that isn't live, which already cancelled NE's restart, so the notice adds no new capability for a forged hold. The early settings write carries nothing but the pending stop.
- **Pause value at every end.** Correct in both places; only N4.

## Task 3: the fixer's list of remaining refusal paths

1. **The user's own acts.** Right.
2. **A lost record.** Right, and now limited to a failed write or damage inside the record map.
3. **The 256 cap.** Acceptable. Slightly imprecise: the admitting owner's own kill-switch record goes as soon as no record without a kill switch is left, not only when all 256 are another owner's. That still needs 256 kill-switch profiles started in one boot.
4. **Notice timing.** Incomplete: L1 is missing. Same second and clock set back are acceptable as written.
5. **A record of another boot.** Right.
6. **A vanished profile file after 120 s.** Acceptable (same-user tampering).
7. **The standing unattended record.** Correctly listed as over-admission.

The closing sentence "nothing else found" holds for provisioning, the passive revoke and capacity. It does not hold for the notice until L1 is fixed. I did not re-verify the update hand-over from a 2.0.1 extension, which the list doesn't cover.

## Task 4: go or no-go

**Go**, with owner-authorised starts in 2.0.2. I would not cut them to 2.0.3 on review grounds.

- Five rounds went from several HIGHs to none, and this round found no new path in the extension's guard, the wire or the persisted state beyond L1.
- L1 errs toward a refused restart, but only at the end of a five-step chain. L2 errs toward an unwanted start of the owner's own profile, and needs the owner's Pause at a visible moment.
- Recommended before the RC build: L1 (two lines and a test) and L2 (one condition and a test). N1 to N4 can go to 2.0.3.
- D-6 stays the gate, since everything here is fakes: E2E-8 with the new rows R4-L1, R4-G, R4-Q, R4-A, R4-P, R4-M4, R4-N2 on real NE. Add one row for L1: R4-G with the profile's rules withdrawn before the outside start and LockPlus relaunched inside the Wi-Fi gap. Any 225 on NE's own restart of a kill-switch session is a cut unless the fix is trivial.
