**1. Clearing the unsigned debt flag preserves the pause-replay attack. Incomplete fix for round-6 #3; the replay pre-exists these commits in 2.0.2.**

[AppSettings.swift:253](native/App/Model/AppSettings.swift:253), [ConnectionStore.swift:2414](native/App/Stores/ConnectionStore.swift:2414), [HeadlessResume.swift:122](native/App/Headless/HeadlessResume.swift:122).

Same-user malware copies a genuine pause, removes its expiry, and lets deletion fail through the GUI’s retries. After quitting, it restores the genuine record and expiry **and removes `pauseValueOwed` or sets it to false**. Restoring the entire original settings file does this too.

Both resume paths then skip the owed-value deletion. The surviving nonce validates the copied record, allowing the signed app to arm/start the profile without fresh consent. This tampering increases authority; it is not merely the “do less” residual described in risk 29(2).

The [new regression](native/Tests/LockPlusTests/Round6FixTests.swift:134) restores only the pause fields, preserving the true debt flag.

**Fix:** Keep revocation state in storage same-user code cannot roll back, available during keychain failure—for example, extension-owned durable state. Consult it before either resume path arms. Test full settings rollback and false/missing flags; signing the flag alone would still permit rollback.

**2. A headless early return loses a failed deletion’s debt. Incomplete round-6 fix; this 2.0.2 replay path remains.**

[HeadlessResume.swift:100](native/App/Headless/HeadlessResume.swift:100), [HeadlessResume.swift:157](native/App/Headless/HeadlessResume.swift:157).

Concrete sequence:

1. Malware retains a genuine expired pause, removes its target, and names a known live manager in `networkRestartHold`.
2. The agent’s deletion at line 149 fails. `spend()` sets only local `owedNow`.
3. The live-manager check returns `.networkRestartPending` before either persistence point.
4. After keychain recovery, malware restores the genuine target and removes the hold. The next run reads false debt and accepts the surviving nonce.

The new agent tests cover completed runs and previously persisted debt. They do not combine a failed deletion with `.networkRestartPending`.

**Fix:** Persist failed consumption inside `spend()`, or guarantee persistence before every subsequent return. Add that exact early-return → recovery → record-restoration sequence, asserting no arm/start.

**3. Launch reconciliation can unregister the helper before the initial spend reports failure. Pre-existing race, incompletely addressed by round 6.**

[AppEnvironment.swift:328](native/App/AppEnvironment.swift:328), [ConnectionStore.swift:2554](native/App/Stores/ConnectionStore.swift:2554), [ConnectionStore.swift:2585](native/App/Stores/ConnectionStore.swift:2585).

With no expiry and initially false debt, `connection.start()` schedules deletion asynchronously. Launch immediately reconciles registration. While deletion is pending, reconciliation can see false debt and unregister the helper. The later failure records debt but never re-registers it.

After retry exhaustion and quit, keychain recovery therefore gets no background consumption. The persisted flag still blocks replay while intact, so this is a narrower cleanup/recovery defect.

The [regression](native/Tests/LockPlusTests/Round6FixTests.swift:127) awaits all deletion attempts **before** reconciliation, missing production’s ordering.

**Fix:** Defer unregistration while consumption is pending and reconcile after its result. Test immediate launch reconciliation against a delayed, failing initial delete.
