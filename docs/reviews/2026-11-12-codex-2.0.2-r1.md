**HIGH**

1. **Automatic recovery can start an OpenVPN profile that never passed validation.** [ConnectionStore.swift:1087](native/App/Stores/ConnectionStore.swift:1087), [ProfilesStore.swift:846](native/App/Stores/ProfilesStore.swift:846).

   Save a profile as “Not yet verified” while the validator is unavailable, then select it for Auto-Connect—the picker permits this. An observed on-demand attempt failing with `profileNotProvisioned` triggers `profiles.provision(p)` followed by `startNow`, without the `engineVerified` check used by ordinary Connect. The reconciliation retry queue likewise admits unverified profiles. This can send even a subsequently rejected or `checkCrashed` payload through OpenVPN/OpenSSL in root.

   **Origin:** Pre-existing unchecked recovery paths bypass the new 2.0.2 boundary. **Fix:** Enforce current, revision-bound verification inside `provision` and every start path; exclude unverified profiles from on-demand plans. Add tests driving unverified/rejected profiles through automatic recovery, asserting no provision, arm, or engine invocation. Current import tests stop at checking the verification flag.

**MEDIUM**

2. **“Save Only” disables crash recovery for a connected kill-switch profile indefinitely.** [ProfilesStore.swift:508](native/App/Stores/ProfilesStore.swift:508), [TunnelController.swift:1772](native/Packages/TunnelEngine/Sources/TunnelEngine/Controller/TunnelController.swift:1772), [AppEditorBackend.swift:58](native/App/Services/AppEditorBackend.swift:58).

   Saving an edit provisions the higher revision and deletes the live session’s authorization. “Save Only” leaves that session running. A later provider crash causes NE’s legitimate nonce replay to receive 225 before protective holding; the kill switch is then open. Unlike the short window described in §20, this lasts until another authorized start.

   **Origin:** New in 2.0.2. **Fix:** Defer the live profile’s replacement until an authorized restart, retaining its payload and replay authorization together. The current higher-revision test asserts authorization deletion; add Save Only → crash → replay coverage and an NE traffic test.

3. **Editable settings turn the signed headless executable into a start-authorization proxy.** [HeadlessResume.swift:83](native/App/Headless/HeadlessResume.swift:83).

   Same-user malware can write an expired `autoConnect.pausedUntil` and an existing manual profile’s UUID into `pausedState.profileID`, then invoke `LockPlus --resume-protection` while the GUI is absent. The genuine signed executable reads this unauthenticated record, calls `armStart`, and starts with the returned nonce. No legitimate pause or unattended-start consent is required; saved credentials can be used.

   **Origin:** Existing settings trust bypasses the new 2.0.2 authorization mechanism. **Fix:** Authenticate resume intent, binding it to profile/revision and expiry, preferably with an extension-issued capability. Apply this to GUI resume too. The headless test fixture currently constructs exactly such an unsigned record and expects a start.

4. **Disabled—or never enabled—Auto-Connect still authorizes external starts.** [ManagerConfiguration.swift:94](native/App/Model/ManagerConfiguration.swift:94), [StartAuthorisation.swift:60](native/Packages/TunnelEngine/Sources/TunnelEngine/Controller/StartAuthorisation.swift:60).

   Selecting a profile while the Auto-Connect toggle remains off still creates a non-nil plan. `ManagerConfiguration` consequently writes `onDemand = true`, although the plan’s `enabled` is false. Another local user’s `scutil` start is then admitted without a nonce. Turning Auto-Connect off also leaves this authorization in place.

   **Origin:** New authorization-policy gap in 2.0.2: rule presence is treated as consent. **Fix:** Represent explicit unattended-start consent separately and revoke it when disabled. Add a manager-plan-to-controller test for selection while off and subsequent disabling; existing authorization tests supply only the final Boolean.

5. **Validation approval can become attached to different payload bytes.** [AppActions.swift:264](native/App/AppActions.swift:264), [ProfilesStore.swift:891](native/App/Stores/ProfilesStore.swift:891).

   Duplicate captures profile metadata before awaiting authentication, but subsequently reads the latest payload by UUID. If an in-flight editor save replaces the source during that wait, the duplicate receives new bytes with the old `engineVerified`, summary, and policy. A replacement saved unverified can therefore inherit approval. Likewise, `verifyPending` applies an old validation result to the current profile without comparing revision or digest.

   **Origin:** Pre-existing asynchronous state handling; newly undermines the validator boundary. **Fix:** Bind approval to `(id, revision, digest)` and commit conditionally. Duplicate one consistent snapshot. Add authentication/validation barriers that allow a replacement before completion.

6. **An IPv6 transport failure is reported as proof of blocking.** [ConnectionSelfTest.swift:132](native/App/Services/ConnectionSelfTest.swift:132).

   For a full IPv4-only profile with protection configured, every non-timeout failure before `ready` becomes `.blocked`. TLS failures, DNS errors, and TCP resets qualify. A malicious network can allow packets out and then refuse TLS, yet the row says “Blocked, nothing leaves outside the tunnel.” `ProbeSession.handle` also discards prior readiness when handling `.failed`.

   **Origin:** New in 2.0.2. **Fix:** Preserve failure type, connection progress, and path evidence. Report transport failures as inconclusive unless local blocking is established. Current tests use one generic refusal; add TLS, DNS, reset, and failure-after-ready cases.

7. **Address overlap can falsely identify physical-interface traffic as tunneled.** [ConnectionSelfTest.swift:116](native/App/Services/ConnectionSelfTest.swift:116).

   `sourceIsTunnel || interfaceIsTunnel` accepts an address match even when the reported interface explicitly differs. If the LAN and VPN use the same private address, a successful request over `en0` is labeled “Through the tunnel.” Interface discovery compounds this by accepting the first interface owning any expected address, including physical interfaces.

   **Origin:** New in 2.0.2. **Fix:** Use the live tunnel’s interface identity and actual connection-path evidence; conflicting or ambiguous ownership must be inconclusive. Add a matching-source/`en0` test and duplicate-address interface fixtures.

**LOW**

8. **The fixed-point check rejects legitimate output of the existing normalizer.** [OVPNNormalizer.swift:392](native/Packages/LockPlusCore/Sources/LPParsing/OpenVPN/OVPNNormalizer.swift:392), [OVPNImporter.swift:140](native/Packages/LockPlusCore/Sources/LPParsing/OpenVPN/OVPNImporter.swift:140).

   An otherwise valid profile containing `link-mtu 1500`, without `mssfix` or `tun-mtu`, suppresses the MSS floor. But normalization drops `link-mtu`. Re-normalizing the resulting canonical payload therefore adds `mssfix`, so the new extension check rejects it. Previously stored profiles can stop connecting after upgrade; this fails closed.

   **Origin:** Pre-existing non-idempotence exposed by 2.0.2. **Fix:** Calculate floors from emitted directives and migrate/revalidate affected stored payloads. Add this case to fixed-point tests; the existing normalizer test explicitly expects no MSS floor, but the fixed-point corpus misses it.

9. **A successful split-tunnel test claims all traffic uses the tunnel.** [ConnectionSelfTest.swift:449](native/App/Services/ConnectionSelfTest.swift:449).

   IPv4 `.outsideExpected`, skipped IPv6, and inapplicable DNS can produce `.ok`. The headline nevertheless says “IPv4, IPv6 and DNS use the tunnel,” with a pass glyph.

   **Origin:** New in 2.0.2. **Fix:** Derive wording from individual results, distinguishing expected bypass and skipped checks. Existing tests explicitly expect `.ok` for this split case but do not verify the headline’s accuracy.

10. **Copy Results can disclose the server address through other rows.** [ConnectionSelfTest.swift:532](native/App/Services/ConnectionSelfTest.swift:532).

    `includeEndpoint: false` only removes the exit-row address. DNS addresses, local source addresses, and error details remain unredacted. If the VPN endpoint is also a DNS server, its address appears in the copied DNS row or route-error detail despite the stated exclusion.

    **Origin:** New in 2.0.2. **Fix:** Redact the complete copied report, including details, using the diagnostics redaction machinery. The current test uses distinct endpoint and DNS addresses, so it misses this overlap.

11. **Opening a FIFO can block the app before confirmation.** [ImportCoordinator.swift:161](native/App/Stores/ImportCoordinator.swift:161), [AppDataStore.swift:123](native/App/Stores/AppDataStore.swift:123).

    A local attacker can supply a named pipe named `profile.ovpn`, or a symlink to one. The importer rejects directories but otherwise performs blocking `open`/read on the main actor. With no writer, it hangs before any confirmation sheet, freezing protection controls. The root tunnel continues independently.

    **Origin:** Pre-existing reader, newly exposed through automatic document opens. **Fix:** Open nonblocking, validate the descriptor as a regular file, and read off the main actor. Router tests use fake sinks; add actual FIFO and symlink cases.

12. **The build-floor tests do not establish dynamic XPC enforcement.** [RequirementTests.swift:112](native/Tests/RequirementTests/RequirementTests.swift:112).

    The tests evaluate ad-hoc fixture bundles using `SecStaticCodeCheckValidity`; they never exercise the listener requirement against an older running peer. They therefore cannot catch failure of the `info [CFBundleVersion]` predicate in the actual XPC path, including a process surviving bundle replacement. **No floor bypass was demonstrated in this review.**

    **Origin:** New 2.0.2 coverage gap. **Fix:** Gate release on live below-floor/at-floor peer tests, including replacement beneath a running process, and verify rejection before delegate invocation.

Tests were inspected, not executed. No files were modified.
