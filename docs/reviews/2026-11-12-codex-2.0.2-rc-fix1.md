**MEDIUM — Timeout can spend the resume authority without restarting protection.**  
[HeadlessRunner.swift:27](native/App/Headless/HeadlessRunner.swift:27), [HeadlessResume.swift:216](native/App/Headless/HeadlessResume.swift:216).

An expired pause of a manual kill-switch profile reaches `spend()`, successfully deleting its one-time value. If execution then stalls inside the synchronous start call before NE accepts it, the independent watchdog calls `_exit`. The next run finds the original pause record but no matching keychain value. It treats the record as changed outside LockPlus, drops the restart target, clears the pause and unregisters the agent. With no on-demand rules, protection remains **OPEN indefinitely**. An unused arm expires; it does not initiate a start.

The spending order predates this patch. **New in this fix:** the watchdog can interrupt synchronous start and persistence operations that the former main-queue timer could not interrupt. `pauseValueOwed` does not recover a successfully deleted value.

**Fix:** establish a durable, authenticated, idempotent resume handoff before consuming the pause authority, and reconcile incomplete admission on the next run. Add fault-injection tests for termination after nonce deletion, during start submission and before the final settings rename. The new runner tests count completion callbacks without terminating the operation; they do not test recovery from these persisted states.
