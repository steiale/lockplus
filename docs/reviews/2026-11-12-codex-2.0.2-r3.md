1. **HIGH — Background provisioning can terminate a legitimate kill-switch replay. New-in-round-3 path; cancellation logic predates 2.0.2.**

   [ProfilesStore.swift:1107](native/App/Stores/ProfilesStore.swift:1107), [TunnelController.swift:1864](native/Packages/TunnelEngine/Sources/TunnelEngine/Controller/TunnelController.swift:1864), [TunnelController.swift:1840](native/Packages/TunnelEngine/Sources/TunnelEngine/Controller/TunnelController.swift:1840).

   Connect kill-switch revision 1, then Save Only an unverified revision 2. NE subsequently restarts revision 1. While that authorised replay is connecting or held, background validation accepts revision 2 and immediately provisions it. `payloadCommitted` calls `endWaitingStart`, which completes the replay with an error and tears down its adapter despite `includeAllNetworks`.

   Preserving the nonce does not protect this sequence: authorisation already succeeded. The failed NE start releases protection; a manual profile can remain down/open. A hostile network can prolong the restart handshake to widen the window.

   **Fix:** Stage replacement payloads during recovery, or preserve the protective pending start while adopting the replacement. Background provisioning must not fail an authorised kill-switch replay.

   **Coverage:** Existing tests provision *before* restarting. Add connected → unverified Save Only → authorised replay pending → validation/provision completes, asserting that NE’s start completion does not fail.

2. **MEDIUM — Auto-Connect consent can be replayed after withdrawal; migration trust remains open indefinitely. Remaining r2 #3; 2.0.2.**

   [ProfilesStore.swift:132](native/App/Stores/ProfilesStore.swift:132), [ProfilesStore.swift:156](native/App/Stores/ProfilesStore.swift:156), [ProfileRepository.swift:238](native/App/Stores/ProfileRepository.swift:238).

   Same-user malware saves a genuine enabled Auto-Connect record, including `choiceTag`. Turning Auto-Connect off clears the JSON tag but leaves its keychain nonce intact. Restoring the saved record and launching LockPlus therefore restores valid unattended-start consent.

   Separately, launches with Auto-Connect disabled never establish a secure migration marker. If the user has never enabled it, an unsigned attacker-written choice is accepted as `.neverSealed` on any subsequent launch—not merely the documented first upgrade launch.

   **Fix:** Persist an initialised/revoked state in the keychain and invalidate the previous consent whenever Auto-Connect is disabled. Close migration eligibility even when the initial choice is disabled.

   **Coverage:** Add enabled → disabled → restore old signed record, and repeated disabled launches → inject unsigned enabled record. Current forged-tag tests cover neither.

3. **MEDIUM — Cancelling recovery cannot revoke its standing authorisation. New-in-round-3 regression; 2.0.2.**

   [ConnectionStore.swift:828](native/App/Stores/ConnectionStore.swift:828), [TunnelController.swift:1323](native/Packages/TunnelEngine/Sources/TunnelEngine/Controller/TunnelController.swift:1323), [TunnelController.swift:1347](native/Packages/TunnelEngine/Sources/TunnelEngine/Controller/TunnelController.swift:1347).

   An unattended kill-switch session loses its on-demand rules, then ends with `noNetwork` or `providerFailed`. During recovery, the user presses Cancel. The app calls `stopVPNTunnel`, but the controller clears authorisation only through `session?.key`; that session has already gone. Reconciliation now permanently excludes kill-switch records from revocation.

   Consequently, after the user explicitly cancelled recovery, another local user can still start that profile without options and use the retained unattended authorisation. This extends beyond risk 29’s stated boundary of “until the user’s stop.”

   **Fix:** Add an owner-authenticated operation that explicitly ends recovery authorisation for a profile/session generation. Keep passive reconciliation distinct from this deliberate cancellation.

   **Coverage:** Add unattended KS → rules withdrawn → non-user end → user cancels recovery → outside start gets 225. The existing user-stop test stops a live session.

4. **MEDIUM — An unsigned recovery hold can become a signed pause target. New-in-round-3 discovery; pre-existing 2.0.2 signing gap.**

   [ConnectionStore.swift:894](native/App/Stores/ConnectionStore.swift:894), [ConnectionStore.swift:2129](native/App/Stores/ConnectionStore.swift:2129), [ConnectionStore.swift:2160](native/App/Stores/ConnectionStore.swift:2160).

   Malware writes `networkRestartHold = B`, naming a saved, disconnected manual kill-switch profile. Launch accepts this unsigned field as a recovery hold without establishing that B ever ran.

   For example, while offline with another profile’s Auto-Connect enabled, the user chooses Pause Protection. With no live session, `pause()` uses the forged hold as its target and signs B. At expiry, that genuine signature permits LockPlus to arm and start B with its saved credentials.

   **Fix:** Authenticate recovery holds when created and verify them before treating them as resumable sessions. An unsigned hold must not supply input to a fresh resume signature.

   **Coverage:** The planted-`pausedState` test now passes, but does not exercise `networkRestartHold`. Add the forged-hold → Pause → expiry sequence and assert no signature or start for B.

5. **MEDIUM — Traffic before `.ready` can still produce green “blocked.” Remaining r2 #5; 2.0.2.**

   [ConnectionSelfTest.swift:142](native/App/Services/ConnectionSelfTest.swift:142), [ConnectionSelfTest.swift:479](native/App/Services/ConnectionSelfTest.swift:479), [ConnectionSelfTest.swift:209](native/App/Services/ConnectionSelfTest.swift:209).

   The sequence `.waiting(noPath)` → `.preparing` on `en0` → timeout retains the original `.noPath`: `.preparing` is ignored, and only `.ready` clears waiting evidence. A hostile network can permit TCP establishment and stall TLS, so packets leave before readiness. Apple describes `.preparing` as connection establishment in progress. [Apple documentation](https://developer.apple.com/documentation/network/nwconnection/state-swift.enum/preparing)

   The timer then returns stale local-refusal evidence, allowing a green IPv6 `.blocked` verdict.

   **Fix:** Track attempts and usable paths before readiness. Clear obsolete waiting evidence when an attempt resumes; uncertainty after an attempted connection must remain inconclusive.

   **Coverage:** Add the actual waiting → preparing → stalled TLS → timeout transition. The new regression exercises waiting → **ready**, leaving this branch untouched.

6. **MEDIUM — The default-route shortcut still overrides contrary IPv6 evidence. Remaining r2 #6; 2.0.2.**

   [ConnectionSelfTest.swift:204](native/App/Services/ConnectionSelfTest.swift:204), [ConnectionSelfTest.swift:325](native/App/Services/ConnectionSelfTest.swift:325), [ConnectionSelfTest.swift:369](native/App/Services/ConnectionSelfTest.swift:369).

   With an IPv4-only full tunnel and Block IPv6 enabled, the blackhole default route can point at the utun. `hasDefaultRoute(excludingTunnels: true)` consequently returns false, although IPv6 remains usable through more-specific physical routes.

   A hostile LAN can advertise an on-link prefix covering the probe destination, receive its packets on `en0`, then stall or return unreachable. Even when the destination-specific lookup reports `en0`, line 204 returns `.noIPv6Here` before considering that evidence. The overall result can be green. Default-route lookup errors also become this same false “absence” evidence.

   **Fix:** Do not infer absent IPv6 from the winning default route. Preserve lookup uncertainty and let attempted-destination evidence prevent a green verdict.

   **Coverage:** Test default=utun, attempted destination=en0, with timeout/unreachable and lookup failures. The current networking fake always returns `hasDefaultRoute == true`.

7. **LOW — Open-event work escapes the five-event cap before its task begins. New-in-round-3; 2.0.2.**

   [ImportCoordinator.swift:279](native/App/Stores/ImportCoordinator.swift:279), [ImportCoordinator.swift:297](native/App/Stores/ImportCoordinator.swift:297), [ImportCoordinator.swift:213](native/App/Stores/ImportCoordinator.swift:213).

   `drainOpenQueue` removes an event and schedules a task without synchronously marking the importer busy. Several open callbacks arriving before those tasks execute each see an empty queue and idle importer. They all start analyses, bypassing the cap and retaining potentially large archive buffers and eventual confirmation sheets.

   **Fix:** Reserve the active-import slot synchronously before scheduling work; count scheduled work toward the bound.

   **Coverage:** Send a burst without yielding to the scheduled tasks. `theOpenQueueIsCapped` first waits for a sheet, masking this race.

8. **LOW — More than 500 retained profiles still disables revocation altogether. Remaining r2 #8; 2.0.2.**

   [ProfilesStore.swift:789](native/App/Stores/ProfilesStore.swift:789).

   The larger wire limit fixes the 500-entry encoding failure, but the app now sends nothing when the keep set exceeds 500. For example, with 501 profiles retaining plans, withdrawing consent from another non-kill-switch profile whose process crashed leaves its unattended record unreclaimed. Subsequent reconciliation repeats the same refusal.

   **Fix:** Batch explicit revocations, or apply a paginated keep set atomically. Do not send independent complement batches, which would revoke each other’s retained entries.

   **Coverage:** Add an app/controller test with more than 500 retained profiles and a separate record that must be revoked. The wire test verifies 500 entries fit and 501 are rejected; it does not verify eventual revocation.

9. **LOW — The final watchdog timeout exposes the next request to the dying service. Remaining r2 #9; 2.0.2.**

   [ValidatorClient.swift:112](native/Packages/LockPlusCore/Sources/LPXPCClient/ValidatorClient.swift:112), [ValidatorClient.swift:118](native/Packages/LockPlusCore/Sources/LPXPCClient/ValidatorClient.swift:118), [ValidatorClient.swift:139](native/Packages/LockPlusCore/Sources/LPXPCClient/ValidatorClient.swift:139).

   On the **second** watchdog timeout, `timedOut()` throws before the exit-grace sleep. The gate releases immediately, and the next queued request can reconnect during the service’s 250 ms exit delay. `serviceTimedOutAt` belongs only to the previous call, so that expected exit counts as a crash of the next input.

   This spends the innocent request’s crash retry; one subsequent actual interruption can incorrectly make its rejection permanent.

   **Fix:** Retain expected-exit state across requests and gate reconnects through service replacement, including final-timeout paths.

   **Coverage:** Use a real service process: request A times out twice, request B immediately follows, and A’s watchdog exit must not count against B. The existing fake returns `.timeout` without exiting.
