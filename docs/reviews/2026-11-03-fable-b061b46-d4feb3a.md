## Findings, most severe first

**LOW-1. Delete's M3 on-demand-off check runs before the awaited start; a save already in flight when Delete begins can land an on-demand-ON manager after it.**
- `native/App/Stores/ProfilesStore.swift:568` (M3 check) vs `:577` (`stopSessionBeforeRemoval`), and `:477` (`syncManager` evaluates `onDemandPlan(for: p)` before the suspension).
- Scenario: Connect of the auto (or stay-connected) kill-switch profile whose manager doesn't exist yet → `syncManager` issues `managers.save(…, onDemand: <enabled plan>)` → Delete clicked while that save is in flight → `delete` sees no manager (M3 skipped), `stopAndWait` → `stop` is a no-op (nothing live) → `await start?.value` → the save lands with on-demand ON → NE may on-demand-start it during the 0.5 s settle → `refuseIfDeleted` (`:499`) ends the task → `waitForSessionEnd` waits the full 10 s (nobody stops that session) → `managers.remove` removes the live configuration (NE tears it down, `.invalid` ends it). Harm: a 10 s delay; if `remove` throws, an on-demand-ON orphan with a live session (`.unaddressable` busy, the sweep never runs) = the original M-1 harm.
- Fix: after `stopSessionBeforeRemoval` returns, repeat the M3 check + `stopAsUser` once (the manager the awaited start may have created), before the remove. Add a test that starts Delete inside the fake's `save` hop.

**LOW-2. `resaveOnDemand` re-creates a configuration for a profile being deleted.**
- `native/App/Stores/ProfilesStore.swift:549`: `want == nil` (deleting) and `have == nil` (removed) → `have?.onDemandEnabled == false` is `nil == false` → false → falls through to `managers.save(…, onDemand: nil)` at `:552`.
- Window: between `managers.remove` (`:585`) and `repository.delete` (`:594`), a `runDeferredSync` from `restoreIfIdle` (the removal's `.invalid`/`configurationChanged` with a pending `hasDeferredSync`). Harm: an on-demand-OFF orphan until the next idle `load()` sweep (extension profile already removed) — the invariant "no configuration re-created for a deleted profile" is still violated. Pre-existing path, but the new `deleting` mark is exactly the guard it lacks.
- Fix: `guard !deleting.contains(p.id)` in `resaveOnDemand`; put `refuseIfDeleted` in `saveOnDemand` and `saveManagerUnlessBlocked` too, so every `managers.save` in the store is covered (today 2 of 6 sites are).

**LOW-3 (pre-existing, not from these commits). Delete of a profile whose start is `.starting(issued: true)` with no status yet holds everything busy for `startingTimeout` (30 s).**

## Regression answers
- **Deadlock**: none. Nothing on the start path waits on the delete; the delete holds no lock while awaiting; `pauseOtherOnDemand` → `restoreTask` → saves/loads on the free lock; `waitUntilSettled` capped. **Ordering**: `startTasks[id]` is assigned in the same synchronous main-actor job that creates the Task, so the body can't run first; cleanup is token-guarded so a newer start's entry isn't cleared. **Cancellation**: the task is awaited, not cancelled; it bails at its next `gone()` and its `restoreIfIdle()` restores what it paused (durable record) — no silent-off. **Leaks**: entries removed on completion; a replaced entry's task runs to completion and is dropped.
- **`deleting` mark**: `defer` clears it on every exit; `delete` is non-throwing with per-step catches. It could persist only if a pre-existing unbounded await hangs (`removeFromPreferences`, XPC). Even then auto-connect isn't *silently* off: `autoConnect.enabled = false` is visible in the pane, same as the end-of-delete state before.
- **`autoConnect.profileID` cleared before a failed removal**: correct — the profile is deleted regardless (every step runs), the orphan is swept at idle.
- **`prepareForStart` refusal**: first-connect create path OK (`profile(p.id)` exists; missing manager → `managerIsBehind` true → saves). Headless `verifyForStart` (`HeadlessResume.swift:132-143`) builds its own store, `load()`s, takes `p` from it → present. No legitimate start refused.
- **Confirm retry**: bounded, verified; the FakeTimers test proves no 4th arm.
- **`startEndedEarly` mapping**: complete.
