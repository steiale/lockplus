# Security review: E2E-7 F3 `tunnelstale` (LegacyHelperRemoval.swift, uncommitted)

**Verdict: nothing exploitable found.** The fail-safe direction holds in every path I could construct: every error, unexpected exit code, non-root owner, symlink, malformed JSON or present utun returns 1 (= busy). No new interpolation of runtime data into the root shell; the only new command substitution is `ifconfig -l`, and its output is used only in a `case` pattern match, never executed. The change does not weaken the pf, identity, DNS-journal or old-app refusals: they all still run after a stale verdict, in the same order (verified in body lines 195-239 and by `staleStateKeepsTheOrder`). The E2E7 suite passes on this Mac (6 tests / 20 cases). Findings below are defence-in-depth and test-quality items, ranked.

Facts established (host, read-only, unprivileged): `launchctl print system/<unknown>` exits 113 and `pgrep -f` exits 1 (none) / 2 (bad regex) exactly as the fakes assume; `/Library/Application Support` is 755 root:admin, `…/lockplus` and `…/lockplus/tunnel-states` are 755 root:wheel (so only root can create, rename or hard-link there; the admin user cannot); 1.x writes the file via `json.MarshalIndent` with `interface_name` from `engine.InterfaceName()` (kernel-assigned, not user-controlled) and `tunnel_name` from the user (`internal/tunnel/connect_phases.go:29-34`, `recovery.go:26-43`); OVPN tunnels never get a state file; openvpn is spawned without `Setpgid` and the plist has no `AbandonProcessGroup`, so launchd kills it with the helper's process group; the 1.x plist has `KeepAlive=true`, so the stale file arises in the respawn-throttle window before a bootout (matches the F3 repro); `do shell script`'s cwd is the calling app's cwd (`/` from Finder, the terminal's cwd when launched from a shell).

## MEDIUM

**M1 — No test parses the body's syntax; the three `sh -n` checks parse only the wrapper.**
`native/Tests/LockPlusTests/E2E5FixTests.swift:204-209`, `E2E6FixTests.swift:121-126`, `MigrationMatrixTests.swift:101-106` all run `sh -n -c LegacyHelperRemoval.script`, i.e. `exec /usr/bin/env -i PATH=… /bin/sh -c '<body>'`. `sh -n` does not parse the contents of a single-quoted string; I verified `sh -n -c "exec /usr/bin/env -i PATH=/usr/bin /bin/sh -c 'if then fi ((('"` exits 0. The new glue lines (`body` 195-197) and the `tunnelstale` *call sites* are therefore never parsed by any test; only the function text itself is (E2E7 executes it). This is pre-existing (since LOW-2's wrapper), but this change is the first to add body lines without any execution path in tests. Consequence of a future body typo: bash executes command lists up to the error (verified: earlier lines run, exit 2), so a syntax error after the bootout would leave a partially removed helper with no `LP_RESULT` line (`.incomplete`), after a spent administrator prompt. Fix: in `E2E5FixTests.theRemovalScriptIsFixedAndChecksBeforeRemoving` also run `sh -n -c LegacyHelperRemoval.body` (and the same in the other two), or replace the wrapper check with the body check plus the `PrereleaseReviewTests.swift:454` identity.

## LOW

**L1 — Newline in a tunnel name splits one state file into two phantom paths; with a matching cwd the live file's utun is never checked.**
`LegacyHelperRemoval.swift:139-150`: `F=$(find … -name '*.json')` is split on `IFS=$NL`. `stateFileName` (`recovery.go:26-30`) only replaces `/`, `\`, `..`, so a user-named tunnel `a.json⏎b` yields a root-written file `a.json⏎b.json`; the loop then checks `…/tunnel-states/a.json` and the *relative* path `b.json` instead of the real file. Reproduced unprivileged with the real function (uid substituted as in the tests): from any normal cwd the relative half doesn't resolve → exit 1 (fail-safe); with cwd = `tunnel-states` and stale `a.json`/`b.json` present, the live-utun file passes → exit 0. Preconditions make this unexploitable in practice (a user-chosen newline name, the root shell's cwd under attacker influence only when LockPlus was launched from a shell, and a utun alive while the helper is dead and unloaded, which WireGuard's utun can't do), so this is hygiene, but the fix is one line: inside the loop add `case "$f" in "$Q/tunnel-states/"*) ;; *) IFS=$OIFS; return 1 ;; esac` before `rootfile "$f"`, and/or `cd /` at the top of the body so no relative path ever resolves under a caller-chosen cwd. Add a test with a newline-named fixture (expect 1).

**L2 — Empty `ifconfig -l` output is treated as "no interfaces", not as an error.**
`LegacyHelperRemoval.swift:138`: `I=$(ifconfig -l) || return 1` guards only the exit status. Reproduced: with the fake printing an empty line and exit 0, `tunnelstale` returns 0 (stale). Real `ifconfig -l` always lists `lo0`, so this is not reachable on macOS, but the function's own contract is "any other answer or error stays busy". Fix: `case " $I " in *" lo0 "*) ;; *) return 1 ;; esac` right after the assignment (a cheap plausibility check that the list is real), and a test with `interfaces: ""` expecting 1.

**L3 — Stale verdict drops 1.x's crash recovery for the endpoint bypass routes; not documented.**
Before this change the user got `busy` and the copy said "or restart your Mac", which started the KeepAlive'd helper, whose `RecoverFromCrash` ran `Cleanup(iface)` (`internal/network/darwin.go:657-685`): `RestoreDNS` (now covered by `journalstale`), interface routes (gone with the utun anyway) and `route delete <endpoint IP>` for the bypass host routes, which survive the crash. After this change the helper is removed and nothing ever deletes those `/32` routes until reboot. Harmless on the same network; after a network change they point at a stale gateway and the *native* app's connect to that same server IP can fail until reboot. Don't fix in the root script (it would require reading file data into a command, against the §13.3a "no runtime data" contract). Fix: note it in DESIGN §13.3a step 2 ("…bypass host routes a hard-killed helper left stay until a restart") and consider emitting an `LP_STALE=tunnel-states` line so the app's removed copy can suggest a restart in that case; owner's call on the second part.

**L4 — Likely false "busy" when the native tunnel reuses the stale utun number.**
`LegacyHelperRemoval.swift:150` and `LegacyAppDetector.swift:436-448`: NE assigns the lowest free `utunN`, and the Go helper's utun was the lowest free when it was created, so after `kill -9` the native 2.0 tunnel very plausibly gets the same number (`utun6` in the E2E-7 repro). `canRemoveHelper` does not consider the native connection state, so the user is prompted for an administrator password and gets "The old LockPlus is still connected or its kill switch is on… Disconnect in the old LockPlus first" (`LegacyHelperViews.swift:168`) while it is the new app that is connected. Fail-safe, but a wrong instruction after a spent prompt. Fix: app-side, refuse before the prompt (or add "disconnect LockPlus first" to the busy copy) while the native tunnel is connected and the detector sees the old `tunnel-states` directory non-empty; cheapest is extending the busy copy.

## NIT

**N1 — `set -f` is never restored** (`LegacyHelperRemoval.swift:143`, same in `journalstale`:74). Globbing stays off for the rest of the body. Everything later is quoted, so this is harmless and arguably safer, but it is an undeclared global side effect; either restore it (`set +f` next to `IFS=$OIFS`) or move `set -f` to the body's first lines next to `umask 077` and document it in the contract.

**N2 — `interface_name` with trailing newlines passes the regex.** `$(plutil … -o -)` strips all trailing newlines, so `"utun6\n"` becomes `utun6` (reproduced: exit 0). Root-written by `json.Marshal` of a kernel name, so unreachable; if you want the regex strict, compare `plutil`'s raw output length or reject `*[![:print:]]*` before the `case`.

**N3 — Comment/doc precision.** `LegacyHelperRemoval.swift:123-129` and DESIGN §13.3a step 2 say "launchd doesn't know the label (exit 113)"; a job that is loaded but currently not running (KeepAlive throttle window, which is exactly the F3 pre-bootout state) exits 0 and is treated as busy, which is correct but worth one clause ("loaded, even if not running → busy") so nobody later "fixes" it to accept exit 0 with no PID.

**N4 — Tests: fixture gaps.** `E2E7FixTests.swift`: add (a) newline-named file → 1 (L1), (b) `interfaces: ""` → 1 after L2, (c) a `.json` that is a FIFO (`mkfifo`) → 1 (rootfile's `-f` covers it; it just isn't asserted), (d) a file name containing glob characters (`a*.json`) → stale (proves `set -f`). The uid-substitution guard (`components(separatedBy: "= 0 ]").count == 3`) is good and should be kept.

## What I checked and found sound
- Trust in `/Library/Application Support/lockplus`: root-only writes; `tunnelstale` additionally requires root owner + non-symlink for the directory and each file; `cleandata` re-checks `$C` and `$C/tunnel-states` (root, `-d`, `! -L`) before `rm -rf`. TOCTOU between the gate and `cleandata` is reachable only by root. Hard links: no write permission on the directory, so none.
- Exit-code assumptions (113, 1) match the host; everything else (0, 2, 3, 5, 127, 128+n) → busy. `pgrep` self-match: `^$3( |$)` can't match `/bin/sh -c …`; `oldAppPattern` and `wireGuide100Pattern` are followed by `(` in the body text, so neither matches the running script's argv (in-process or osascript fallback). Native `…/MacOS/LockPlus` is case-mismatched as documented.
- `plutil`: `-expect string` plus the strict `utun[0-9]{1,3}` `case` and the space-delimited `ifconfig` match; JSON shape attacks are moot (root-written) and the malformed matrix in the tests is good.
- `env -i`/PATH unchanged; no `eval`, no new `$(…)` beyond `ifconfig`; `E2E5` substitution allowlist updated accordingly.
- `D3`'s fourth argument is single-quoted in the body and survives the `'\''` wrapping (checked in `wrapped`).
- Ownership/`stat -f %u` after `! -L` in both `rootfile` and the directory check: correct order.

Scratch left at `<build dir>/sec-e2e7-scratch` (fixture files, fake `launchctl`/`pgrep`/`ifconfig`, extracted `funcs.sh`); nothing in the repo was modified, nothing ran as root, host `/Library` untouched.

---

**Fixes.** All findings (M1, L1–L4, N1–N4) were fixed before the F3 commit: the body is now parsed by `sh -n` in the tests, a file-name prefix check and `cd /` guard the loop, an empty interface list fails closed, a stale verdict is reported to the user (`LP_STALE=tunnel-states`), a busy answer while LockPlus 2 is connected gets its own message, `set -f` is set once for the whole body, `interface_name` is compared raw, and the fixtures cover newline, FIFO and glob file names. Full Unit plan: 650 tests, 0 failed.
